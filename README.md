# Vanilla RAG: корпоративная база знаний

Полный эксперимент выполнен 25.09.2026 в Google Colab на NVIDIA T4: 10 статей, 50 вопросов и 50 эталонов преподавателя, три режима по 50 ответов. Сохранены код, ответы, контексты, оценки и ноутбук с выводами.

## Результаты

| Режим | BLEU /100 | ROUGE-1 | ROUGE-2 | ROUGE-L | LLM judge /4 |
|---|---:|---:|---:|---:|---:|
| Groq zero-shot | 3.55 | 0.229 | 0.112 | 0.210 | 0.64 |
| Локальная Qwen zero-shot | 3.31 | 0.225 | 0.100 | 0.208 | 0.24 |
| Groq + RAG | **36.60** | **0.659** | **0.503** | **0.622** | **3.68** |

Добавление источников к той же API-модели повысило оценку судьи на **3.04 балла из 4**, BLEU — на 33.06 пункта. Судья оценил 46 из 50 RAG-ответов на 4/4; четыре получили 0/4. Это наблюдение на небольшом golden test set, не доказательство статистической значимости или универсального превосходства.

Во всех четырёх ошибках правильный факт присутствовал в первом найденном фрагменте, но генератор ответил «В базе знаний нет ответа». Для этих примеров проблема — использование контекста. [Разбор ошибок](results/ERROR_ANALYSIS.md), [автоматический отчёт](results/REPORT.md).

## Модели и пайплайн

| Компонент | Настройка |
|---|---|
| API baseline и RAG | openai/gpt-oss-20b, Groq, temperature=0, reasoning_effort=low, max_tokens=2048 |
| Локальный baseline | Qwen/Qwen2.5-1.5B-Instruct, vLLM 0.11.0, fp16, T4, temperature=0, seed=42, max_tokens=256 |
| Общий судья | openai/gpt-oss-120b, Groq, temperature=0, reasoning_effort=low |
| Embeddings | intfloat/multilingual-e5-small, CPU, нормализация, префиксы passage: / query: |
| Разбиение | RecursiveCharacterTextSplitter, 700 символов, overlap=120; 30 фрагментов |
| Поиск | LangChain InMemoryVectorStore, top_k=4 |

LangChain связывает Document, splitter, embeddings, vector store, retriever и ChatGroq. Индекс включает **только статьи**. Эталоны используются исключительно для оценки. Генератор получает вопрос и четыре фрагмента с ID статей; инструкция требует отвечать по источникам и игнорировать инструкции внутри них. Zero-shot модели получают вопрос без источников. Параметры читаются из [configs/default.json](configs/default.json).

Разные размеры и лимиты вывода моделей означают, что сравнение двух zero-shot baseline не является контролируемым сравнением архитектур. Основное сравнение RAG/zero-shot использует одну API-модель.

## Метрики

- Corpus BLEU (SacreBLEU), шкала 0–100, tokenize=none, effective_order=True, экспоненциальное сглаживание; предварительная Unicode-токенизация и нижний регистр.
- ROUGE-1/2/L: средний F1 по 50 парам, шкала 0–1. Собственный tokenizer сохраняет кириллицу и числа.
- LLM-as-judge: единая рубрика 0–4, от неверного/отсутствующего до полностью верного ответа. Судья видит вопрос, эталон и ответ, но не название режима; сохраняются JSON-оценка и объяснение. Невалидный JSON повторяется до трёх раз, затем выполнение останавливается.

BLEU/ROUGE чувствительны к формулировке. Судья может ошибаться; он и генератор принадлежат одному семейству GPT-OSS. 46/50 — оценка судьи, не независимая ручная оценка всей выборки. Ручной разбор охватывает четыре ошибки. Детерминизм внешнего API не гарантируется.

## Запуск в Colab

1. Откройте [ноутбук повторного запуска](https://colab.research.google.com/github/evelinashakhnazaryan/rag-homework/blob/rag-experiments/notebooks/02_reproduce.ipynb).
2. Выберите GPU T4. В Secrets добавьте GROQ_API_KEY и разрешите доступ ноутбуку.
3. Выполняйте ячейки сверху вниз: клонирование проекта с данными, зависимости, валидация, три режима, отчёт.
4. Скачайте выполненный .ipynb через «Файл → Скачать» и архив результатов из последней ячейки.

Новый запуск пишет в results_reproduction/, не смешивая ответы с опубликованными. Квоты Groq и наличие GPU зависят от аккаунта. Ключ не сохраняется в коде и Git.

## Скрипты

Полный эксперимент требует Linux с NVIDIA GPU (проверено в Colab, Python 3.13.15). Для совместимости закреплены vLLM 0.11.0 и Transformers 4.57.1.

```bash
python -m pip install -r requirements-colab.txt
# Задайте GROQ_API_KEY в окружении.
# Для нового эксперимента скопируйте конфиг и смените results_dir.
python -m src.run --config configs/default.json --mode validate
python -m src.run --config configs/default.json --mode groq_zero
python -m src.run --config configs/default.json --mode local_zero
python -m src.run --config configs/default.json --mode groq_rag
python -m src.report --config configs/default.json
```

С заполненным results/ используется checkpoint. Для независимого прогона нужен новый results_dir. Fingerprint предотвращает смешивание ответов при изменении конфигурации или данных. Ответы и оценки сохраняются после каждого вопроса.

Проверка данных, пересчёт отчёта и тесты не требуют GPU или ключа:

```bash
python -m pip install -r requirements.txt
python -m src.run --mode validate
python -m src.report
python -m unittest discover -s tests -v
```

## Файлы и доказательства выполнения

- src/: данные, модели, поиск, оценка, запуск, аудит и отчёт; data/: три исходных JSON, сопоставление по ID.
- notebooks/00_validation.ipynb: выполненные проверки данных и Unicode.
- notebooks/01_colab.ipynb: реальный выполненный журнал, включая исправления совместимости среды.
- notebooks/02_reproduce.ipynb: чистый вход для повторного запуска, намеренно без выводов.
- results/*_zero.json и groq_rag.json: 150 ответов, эталоны, оценки и контексты RAG; *_metrics.json: точные метрики.
- results/chunks.json и index.json: фрагменты и индекс; manifest.json: конфиг, SHA-256 данных и начальная среда; environment_final.json: версии после исправления совместимости.

Исходный manifest сохранён без переписывания истории. Журнал 01 использовал исходный ZIP проекта и исправлял зависимости в процессе; для запуска с нуля используйте 02. Предупреждения установки и завершения vLLM сохранены: все 50 локальных ответов получены, процесс завершился с кодом 0. После прогона отчёт исправлен, чтобы показывать только оценки ниже 4; исходный вывод журнала включает также корректный q2 среди пяти наименьших оценок.

## Замечания преподавателя и проверки

Ноутбук сохранён с реальными выводами и вызывает .py-модули. Конфигурация подключена, цифры и кириллица сохраняются, неиспользуемого competition_test_df нет. Шесть unit-тестов проверяют валидацию ID, Unicode и метрики. Агрегаты дополнительно пересчитаны из сохранённых 150 ответов и сверены с результатами.

## Улучшения

Нужна отдельная validation-выборка для выбора chunk_size/top_k и prompt. Текущий golden test не использовался для подбора параметров. Следующие шаги: проверка необоснованных отказов, цитаты в ответах, независимый судья, hybrid BM25+dense поиск и reranker. Разметка релевантных фрагментов позволит измерить Recall@k на всех вопросах. Наличие ответа в top-1 проверено только для четырёх ошибок, это не полная retrieval-метрика. Также стоит устранить фрагменты, содержащие только заголовок, и проверить эффект на отдельной выборке.
